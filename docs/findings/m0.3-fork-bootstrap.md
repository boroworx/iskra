# M0.3 — Fork bootstrap

**Verdict:** the fork installs and runs locally with seeded data. Server and web both come up
from a worktree with no code changes.

## What `vp` is

`vp` is the global [Vite+](https://viteplus.dev) CLI (voidzero). It wraps the pnpm workspace
(`packageManager: pnpm@11.10.0`) and runs tasks, lint and tests. The repo pins `vite-plus` 0.3.0
as a dev dependency; the global CLI was 0.3.1.

Install (macOS/Linux): `curl -fsSL https://vite.plus | bash`. The installer adds
`~/.local/share/vite-plus/bin` to PATH via `~/.zshenv` / `~/.zshrc`. Set `VP_NODE_MANAGER=no` to
stop it from taking over the system `node`, `pnpm` and `bun` binaries with shims.

## Runtime

- The repo declares Node `^24.13.1`. Node 26.5 installed and ran dev without errors.
- Bun is optional (`docs/operations/development.md`), not the runtime.

## Steps that worked

1. `vp i`: about 4.5 min cold, pnpm 11.10.0. The only warning was about peer dependencies.
2. Seed state by snapshotting the real database with `VACUUM INTO` (Node's built-in
   `node:sqlite`, so Bun isn't needed):

   ```sh
   mkdir -p .t3/userdata && rm -f .t3/userdata/state.sqlite*
   node -e "const {DatabaseSync}=require('node:sqlite'); new DatabaseSync(process.env.HOME+'/.t3/userdata/state.sqlite',{readOnly:true}).exec(\"VACUUM INTO '.t3/userdata/state.sqlite'\")"
   ```

3. `vp run dev`: the dev runner picked `source=worktree`, `baseDir=<worktree>/.t3`, server port
   15434, web port 7394. Migrations ran on the seeded database and the server printed a pairing URL.

## Evidence
