# M0.1: mid-turn input delivery

**Question.** When a user message is sent while a provider turn is running, is it delivered
immediately, queued to the turn boundary, or rejected?

**Verdict.** Nothing delivers immediately and nothing rejects. Claude is verified: the message
waits for the next agent-loop boundary, which is the end of the running tool call or the end of
the turn, taking 4 to 19 s in the repros. Codex is code-derived only. **The DM view needs a
pending-message state**, and today T3 shows the message as landed the moment it is sent.

### Latency (Claude, haiku, CLI 2.1.270)

| Scenario                                 | Sent   | Consumed by agent                 | Wait                                      | Turns                                         |
| ---------------------------------------- | ------ | --------------------------------- | ----------------------------------------- | --------------------------------------------- |
| During `sleep 20` Bash call              | 9.07 s | 27.76 s (right after tool_result) | **18.7 s** (rest of the tool call)        | 1 result, `num_turns=2`, answer "DONE BANANA" |
| Tools disabled, sent on first text delta | 4.39 s | 8.25 s (after result #1)          | **3.9 s** (rest of generation + new init) | 2 results; first answer ignores the message   |

Worst case is unbounded: it equals the remaining duration of whatever tool or generation is in
flight.

### T3 consequence (code-derived, not run through a T3 server)

For Claude with no tool call left, the adapter has already returned the old `turnId` as if the
message steered that turn. The CLI's result #1 then completes that turn (`ClaudeAdapter.ts:2559`
onward). The reply to the queued message arrives with no active turn and becomes a **synthetic
turn** (`ClaudeAdapter.ts:167-173`). So the UI shows: user message (landed at once), turn
completed without addressing it, then a synthetic turn answering it.

## Reproductions

Claude: runs the `claude` CLI over stream-json, the wire the Agent SDK uses.
`--replay-user-messages` echoes each message when the CLI consumes it, which is how acceptance
time is measured.

```
node docs/findings/repro/m0.1-claude-mid-turn.ts tool
node docs/findings/repro/m0.1-claude-mid-turn.ts text
```

Codex: talks to `codex app-server` over JSON lines. `start` is what T3 does; `steer` is the
native call.

```
node docs/findings/repro/m0.1-codex-mid-turn.ts start
node docs/findings/repro/m0.1-codex-mid-turn.ts steer
```

**Codex was not run.** This machine has no `codex` binary, no `~/.codex/auth.json` and no
`OPENAI_API_KEY`. The script is unexecuted. Run both modes once Codex is installed and logged
in, then replace the Codex column above with the observed behaviour.
